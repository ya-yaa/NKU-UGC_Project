\section{研究背景与意义}

随着互联网平台和移动社交媒体的快速发展，社交网络已经成为信息传播、用户交互和群体行为演化的重要载体。微博、Twitter、Facebook 等平台在长期运行过程中积累了海量的用户关系数据、文本属性数据和行为标签数据，这些数据通常可以抽象为由节点、边、属性和标签共同构成的复杂图结构。围绕这类图数据开展节点分类、社区发现、关系预测和传播分析，不仅能够为社交推荐、舆情监测和用户画像等实际应用提供技术支撑，也具有较高的研究价值。因此，面向社交网络的图数据分析已经成为图挖掘与图机器学习领域的重要研究方向。

近年来，图神经网络在图结构数据建模任务中表现出了优良的性能，尤其在节点分类等任务上取得了较好的效果。然而，随着社交网络规模的持续增大，原始图往往呈现出节点数量多、边连接稠密、属性维度高和结构关系复杂等特点，直接在原图上进行图学习会带来较高的存储开销和计算成本。同时，社交网络中的局部结构往往存在较强冗余，不同节点之间可能具有相近的属性模式和相似的连接关系，使得原始图中包含了大量可压缩的信息。在这种背景下，如何在尽可能保留原图关键信息的前提下减小图规模、提升分析效率，成为图学习和社交网络分析中的关键问题。

图缩减技术为解决上述问题提供了有效思路。与传统的图采样或简单删边删点方法相比，图粗化更强调在压缩图规模的同时保留原图的重要结构特征、谱性质及下游任务性能。图粗化通过将原图中的多个相似节点聚合为超节点，构造规模更小的粗图，从而降低计算复杂度，并为大规模图上的学习与分析提供更高效的数据表示。UGC（Universal Graph Coarsening）方法作为一种具有代表性的图粗化方法，能够结合节点特征与结构信息实现图压缩，并在下游图神经网络任务中体现出较好的应用潜力。因而，围绕 UGC 方法开展适应社交网络场景的研究，具有较强的理论意义和工程价值。

与此同时，真实社交网络数据还具有标签复杂、语义交叠明显和分析流程链条长等特点。尤其是在多标签场景下，节点之间的相似关系难以通过单一标签直接刻画，这使得图粗化方法在社交网络上的应用面临更高要求。因此，如何结合社交网络数据特点，探索更适用的图粗化分析方法，并进一步提升分析流程的效率与可用性，成为值得研究的问题。

从理论意义上看，面向社交网络场景研究图粗化方法，有助于拓展图缩减技术在复杂图数据上的应用范围，并为图学习任务中的高效表示提供新的思路。从应用意义上看，若能够在较好保留原图关键信息的基础上实现图规模压缩，将有助于降低社交网络分析中的计算成本，提高节点分类等任务的执行效率，并为社交推荐、用户分群、行为分析和舆情监测等应用提供支撑。除此之外，将图粗化方法与系统实现相结合，也有助于推动相关研究从算法验证走向实际分析平台，为后续研究和应用扩展奠定基础。

综上所述，在社交网络规模持续增长、图学习计算代价不断上升的背景下，研究基于图粗化的社交网络分析方法及其系统实现，具有较强的理论意义和现实价值。

\section{国内外研究现状}

随着图数据在社交网络、推荐系统、生物信息学和知识图谱等领域中的广泛应用，面向大规模图的高效表示与分析逐渐成为国内外研究热点。根据近年来图缩减领域的综述与文献整理，当前相关研究大致可以分为图稀疏化、图粗化、图凝缩和图摘要等方向\cite{hashemi2024comprehensive}。其中，图粗化通过将原图节点聚合为超节点构造粗图，在兼顾结构保持、谱性质保持和计算加速方面具有较强优势，因而成为连接传统图压缩方法与现代图学习任务的重要研究方向\cite{chen2022graph}。

在国外研究方面，图粗化相关工作起步较早，早期主要集中在图划分、多层次结构组织和谱近似等方向。Kernighan 和 Lin 提出的图划分启发式方法为后续图划分与图缩减研究提供了早期思路\cite{kernighan1970efficient}。Karypis 和 Kumar 提出的多层次图划分框架则进一步推动了多尺度图组织方法的发展\cite{karypis1998fast}。随着图机器学习的发展，研究重点逐渐转向面向下游任务的图压缩。Chen、Saad 和 Zhang 对图粗化从科学计算到机器学习的发展路径进行了系统总结\cite{chen2022graph}；Hashemi 等人进一步将图稀疏化、图粗化和图凝缩纳入统一框架，说明图规模压缩已成为图学习研究的重要基础问题\cite{hashemi2024comprehensive}。在具体方法上，Loukas 从理论上研究了图缩减中的谱保持与割保持问题\cite{loukas2019graph}。Ying 等人提出的 DiffPool 推动了粗化思想与图神经网络任务的结合\cite{ying2018hierarchical}；Cai、Wang 和 Wang 则进一步提出了基于神经网络学习粗图边权分配的数据驱动图粗化方法，体现了图粗化与任务优化相结合的发展趋势\cite{cai2021graph}。Kataria、Kumar 和 Jayadeva 提出的 UGC 方法进一步体现了图粗化向通用化和任务导向化发展的趋势\cite{kataria2024ugc}。

在国内研究方面，相关工作总体上与国际研究趋势保持一致，重点集中在大规模图计算优化、图神经网络加速和图压缩训练等方向。虽然不少研究未直接使用“图粗化”这一名称，但在高效图学习方面已开展了较多探索。例如，马煜昕等针对大规模图训练中的特征加载瓶颈，提出基于输入特征稀疏化的图神经网络训练加速方法，在保证模型精度基本稳定的前提下显著降低了内存占用并提高了训练效率\cite{ma2024sparsification}。总体来看，国内研究在工程实现和应用适配方面较为突出，但在复杂标签场景下的粗化质量评价和系统化集成方面仍有进一步拓展空间。

在图神经网络与社交网络分析研究方面，近年来 GCN\cite{kipf2016semi}、GraphSAGE\cite{hamilton2017inductive}、GAT\cite{velivckovic2017graph}、GIN\cite{xu2018powerful} 等模型已经广泛应用于节点分类、社区识别、关系预测和用户行为分析等任务。然而，现有 GNN 模型在面对大规模社交网络时仍然存在训练成本高和推理效率受限等问题。为缓解这些问题，研究者提出了采样训练、图池化和图缩减等多种方法，其中图缩减和图粗化为提升训练效率、降低数据冗余提供了新的解决方案\cite{chen2022graph,hashemi2024comprehensive}。

除结构规模问题外，社交网络数据本身的标签复杂性也是当前研究中的重要难点。在真实社交网络中，用户通常具有多重兴趣、身份和行为属性，因此多标签数据十分常见。相关综述研究指出，当标签之间存在交叉、包含和弱边界关系时，建模标签相关性是提升多标签学习效果的重要途径\cite{zhang2013review}。这为多标签图学习提供了基础，但在图粗化场景下，如何将多标签信息转化为适合粗化的相似性刻画方式，仍然缺乏统一而成熟的方案。

总体来看，现有研究已经为图缩减、图神经网络和多标签图分析提供了较好基础，但在社交网络场景下，粗化质量与下游任务性能之间的协同优化、复杂标签信息的有效利用以及全流程分析支持等方面仍有进一步研究空间。

基于上述研究现状，本文以 UGC 图粗化方法在社交网络场景下的适用性与可用性为切入点展开研究。具体研究内容与主要工作将在下一节中进一步说明。

\section{研究内容与主要工作}

本文围绕基于 UGC 的社交网络图粗化方法改进与系统实现展开研究。在分析现有方法与系统需求的基础上，结合社交网络数据的结构特征和标签特点，对图粗化过程中的关键问题进行了研究，并完成了图粗化分析系统的设计与实现。本文的主要工作概括如下。

\begin{enumerate}
  \item 图粗化方法效果分析与优化。本文首先基于社交网络数据集对 UGC 方法进行实验分析，发现原始方法在谱性质保持方面表现较好，但在部分数据集上的下游 GNN 分类效果仍不理想。针对这一问题，本文从超节点标签与特征两个层面对粗化结果进行分析，并在特征聚合方式上进行改进，以提升粗化图在下游分类任务中的表现。

  \item 粗化质量评价指标补充。针对现有图粗化评价方法主要关注压缩率、谱误差和分类结果，而对超节点内部标签一致性刻画不足的问题，本文引入平均标签纯度和低纯度超节点占比两个指标，用于从标签一致性角度对粗化质量进行辅助分析，从而为图粗化结果评价提供更细粒度的依据。

  \item 多标签数据处理策略比较。考虑到社交网络数据中普遍存在多标签、弱边界和标签交叠等特点，本文面向多标签数据集设计了多种标签处理策略，并对不同策略下的异配系数、图粗化结果和下游分类效果进行了对比分析，以考察多标签处理方式对图粗化方法适配性的影响。

  \item 图粗化分析系统设计与实现。结合图粗化实验分析的实际需求，本文设计并实现了一个基于 UGC 的社交网络图粗化分析系统。该系统打通了从数据处理、参数配置、图粗化运行到结果导出、GNN 分类测试和可视化展示的完整流程，实现了图粗化实验过程与结果的集成化分析，为相关方法验证和后续扩展提供了系统支撑。
\end{enumerate}

\section{图粗化理论与常用方法}

图粗化是图缩减的重要分支，其基本思想是在尽可能保留原图关键信息的前提下，将多个相似节点聚合为超节点，从而构造规模更小的粗图，以降低存储与计算开销\cite{chen2022graph,hashemi2024comprehensive}。与图稀疏化主要减少边数量不同，图粗化通常同时压缩节点和边；与图凝缩侧重训练样本压缩不同，图粗化更强调对原始图结构、谱性质以及局部拓扑关系的保持\cite{hashemi2024comprehensive}。因此，图粗化已成为面向图学习任务的重要预处理技术。

从形式化角度看，设原图为 $G=(V,E,X)$，其中 $V$ 表示节点集合，$E$ 表示边集合，$X$ 表示节点特征。图粗化的目标是学习一个由原节点到超节点的映射关系，并据此构造粗图 $G_c=(V_c,E_c,X_c)$，其中 $|V_c| \ll |V|$。理想的粗图不仅应在规模上显著小于原图，还应尽可能保持原图的拓扑结构、谱性质和对下游任务有用的特征信息\cite{chen2022graph,loukas2019graph}。

现有图粗化方法通常可以分为两类：一类更关注谱性质保持，常用于谱聚类、图信号处理和科学计算等场景\cite{loukas2019graph}；另一类更关注图挖掘与图学习任务中的表示能力，希望粗图能够较好保留社区结构、局部邻域关系和节点特征信息\cite{chen2022graph}。在实现机制上，图粗化既可以基于传统的图划分与多层次优化思想实现，也可以通过可学习的分配关系构建层次化图表示\cite{kernighan1970efficient,karypis1998fast,ying2018hierarchical,cai2021graph}。[插图建议：可在此处插入“图粗化基本流程示意图”，展示原图经过节点聚合生成粗图的过程。]

对于图粗化结果的评价，现有研究通常从压缩率、结构保持程度和任务性能三个方面展开\cite{chen2022graph,hashemi2024comprehensive}。其中，压缩率反映图规模降低的程度，结构保持程度反映粗图对原图信息的保留能力，而任务性能则关注粗图在节点分类等下游任务中的表现。UGC（Universal Graph Coarsening）是近年来提出的一种具有代表性的通用图粗化方法，其特点是在统一框架下综合考虑图结构信息、节点特征信息以及图的异配程度，从而提升方法在不同类型图数据上的适用性\cite{kataria2024ugc}。考虑到本文后续章节将围绕 UGC 的具体流程、改进方法及实验结果展开分析，本节仅对图粗化技术作概括介绍，UGC 的详细过程将在第三章中进一步说明。

\section{图神经网络分类方法}

图神经网络（Graph Neural Networks, GNN）是一类面向图结构数据的深度学习方法，其核心思想是通过节点之间的连接关系对邻域信息进行传播与聚合，从而学习节点表示并完成分类、预测等任务\cite{kipf2016semi,hamilton2017inductive}。与传统仅依赖节点属性的分类方法相比，图神经网络能够同时利用节点特征和图结构信息，因此在社交网络分析中具有较强的适用性。对本文而言，图神经网络主要用于节点分类测试，以衡量图粗化前后在下游任务上的性能变化。

从模型机制上看，现有图神经网络大多遵循“消息传递—邻域聚合—表示更新”的基本框架，即节点先接收邻居节点传递的信息，再通过聚合函数整合邻域表示，最后更新自身嵌入向量\cite{hamilton2017inductive,velivckovic2017graph}。不同模型的差异主要体现在邻域采样方式、聚合函数形式以及权重分配机制上，但其共同目标都是获得更能反映图结构与节点属性的低维表示。[插图建议：可在此处插入“图神经网络消息传递通用流程图”，用于概括消息传递、聚合和更新三个步骤。]

结合当前系统实现，项目中的 GNN 分类测试模块支持 GCN、GraphSAGE、GAT、GIN、APPNP 和 3WL 等模型。其中，GCN 通过归一化邻接矩阵实现局部邻域信息聚合，结构简洁，是节点分类任务中的经典基线模型\cite{kipf2016semi}；GraphSAGE 采用邻域采样与归纳式聚合机制，更适用于大规模图场景\cite{hamilton2017inductive}；GAT 在聚合过程中引入注意力机制，能够为不同邻居分配不同权重\cite{velivckovic2017graph}；GIN 则通过更强的聚合函数设计提升对局部结构差异的表达能力\cite{xu2018powerful}。此外，系统还集成了基于传播机制的 APPNP 模型以及 3WL 模型，用于进一步丰富分类测试与对比分析的模型选择。

在本文的研究中，图神经网络分类方法主要作为粗化效果的下游评价手段。若粗图在显著缩减图规模的同时，仍能保持较好的分类性能，则说明粗化过程较好保留了对任务有用的信息。因此，本节对图神经网络分类方法作简要介绍，后续实验章节将结合具体模型对图粗化结果进行对比分析。

\section{系统开发技术}

\section{面向社交网络的 UGC 方法分析与优化}

\subsection{UGC方法原理与流程}

通用图粗化（Universal Graph Coarsening, UGC）是一种面向图学习任务的高效图粗化方法，其核心目标是在显著压缩图规模的同时，尽可能保留原图的结构信息、谱性质以及对下游任务有用的语义表示\cite{kataria2024ugc}。与传统图粗化方法主要依赖结构相似性、且多面向同配图设计不同，UGC 在统一框架下同时考虑节点属性与邻接结构信息，并利用图的异配程度调节二者在节点表示中的作用，从而增强了方法对不同类型图数据的适用性\cite{kataria2024ugc}。

从执行流程看，UGC 主要包括增强节点表示构造、基于局部敏感哈希的节点聚合、粗图结构生成以及超节点标签与特征构建等环节，并可进一步结合谱性质保持指标与下游分类性能对粗化效果进行评估\cite{kataria2024ugc,chen2022graph}。

UGC 的第一步是构造增强节点表示。原论文认为，仅依赖节点特征或仅依赖图结构都难以全面描述节点间相似性，因此将节点属性向量与邻接向量进行融合，并通过异配系数 \(\alpha\) 调节二者权重。对任意节点 \(v_i\)，其增强表示可写为
\[
F_i=(1-\alpha)\cdot X_i \oplus \alpha\cdot A_i,
\]
其中，\(\oplus\) 表示向量拼接。该表示方式使节点属性信息与局部结构信息能够在统一空间内共同刻画节点相似性，为后续节点聚合提供基础\cite{kataria2024ugc}。

在获得增强表示后，UGC 采用局部敏感哈希（Locality Sensitive Hashing, LSH）实现节点分桶与聚合。其基本思想是通过随机投影将表示相近的节点映射到同一哈希桶中，再将同桶节点聚合为同一个超节点。该过程避免了复杂的全局匹配或迭代优化，因此具有较高的计算效率。经过哈希分桶后，可得到原节点到超节点的映射关系 \(\pi:V\rightarrow V_c\)，并进一步形成粗化矩阵 \(C\)\cite{kataria2024ugc}。

在节点聚合完成后，UGC 进一步构造粗图的结构信息。若两个超节点对应的原节点集合之间存在边连接，则在粗图中建立对应的超边，其边权由原图中相关边权累加得到。矩阵形式下，粗图邻接矩阵可表示为
\[
A_c=C^{T}AC.
\]
这意味着粗图结构本质上是对原图连接关系在超节点层面的重新组织与压缩\cite{kataria2024ugc}。

除粗图结构外，UGC 流程还包括超节点标签与超节点特征的生成，这两部分对于后续节点分类任务尤为关键。原论文采用超节点内部节点标签的多数类作为该超节点标签；对于超节点特征，则采用簇内节点特征的平均聚合方式生成粗图特征表示。由此可见，UGC 的完整流程不仅涉及“如何聚合节点”，还涉及“聚合后超节点的标签如何确定、特征如何表示”两个关键问题，而这也正是后续优化设计的重要切入点\cite{kataria2024ugc}。

\subsection{UGC存在问题分析}

虽然 UGC 在方法设计上兼顾了图结构信息、节点特征信息与异配特性，并在原始论文中表现出较好的通用性，但结合本文针对社交网络数据集的实验结果可以发现，原始 UGC 在实际应用中仍存在进一步优化空间。总体来看，这些问题主要体现在以下两个方面：
\begin{enumerate}
    \item 在单标签社交网络数据集上，UGC 对谱性质的保持效果总体较好，但其下游 GNN 分类性能并不总是理想。
    \item 在多标签社交网络数据集上，原始方法并未直接回答多标签信息应如何参与节点关系刻画的问题，不同的标签处理方式会显著影响粗化结果与分类效果。
\end{enumerate}
因此，有必要分别从单标签和多标签两个角度对 UGC 进行进一步分析。本文实验共选取了单标签与多标签两类典型图数据集。其中，单标签数据集包括 Blogcatalog、Flickr 和 Tweibo\_sampled，并选取原论文中常用的 Cora 与 Citeseer 作为参照；多标签数据集包括 Facebook 和 Twitter。上述数据集在图规模、结构特性、节点属性维度以及标签空间复杂度等方面存在明显差异，因而能够从不同角度反映 UGC 及其改进方法在社交网络场景中的适用性与泛化能力。各数据集的详细统计信息见附录第一部分。

结合 \ref{tab:single_label_ugc_result} 可以看出，UGC 在单标签社交网络数据集上对谱性质的保持总体较好，但分类性能并不完全与之同步。本文主要采用平均特征值误差和 Dirichlet Energy 相对误差对粗化前后的谱性质保持情况进行刻画。其中，平均特征值误差用于衡量原图与粗图在拉普拉斯谱上的整体偏差，误差越小，表明粗图对原图谱结构的保持越好；Dirichlet Energy 相对误差则反映粗化后图信号平滑性相对原图的变化程度，其值越小，说明粗图在图信号能量层面越接近原图。

谱性质保持较好而下游分类任务效果不佳，说明问题可能出现在超节点层面的语义表达上，即粗化后超节点的标签一致性或特征表示方式可能不足以支撑后续分类任务。为进一步刻画超节点内部的标签聚合质量，本文引入平均标签纯度和低纯度超节点占比两个指标。

设粗图共有 $M$ 个超节点，第 $i$ 个超节点记为 $S_i$，其包含的原始节点数为 $|S_i|$。记超节点 $S_i$ 内出现次数最多的标签所占比例为
\[
p_i=\frac{\max\limits_{c \in \mathcal{C}} n_{ic}}{|S_i|},
\]
其中，$n_{ic}$ 表示超节点 $S_i$ 中属于类别 $c$ 的原始节点数量，$\mathcal{C}$ 表示标签集合。则平均标签纯度定义为
\[
\mathrm{AvgPurity}=\frac{1}{M}\sum_{i=1}^{M} p_i.
\]
该指标反映所有超节点在标签一致性上的平均水平，其值越大，说明粗化后超节点内部的标签越集中。

进一步地，给定纯度阈值 $\tau$，若某超节点满足 $p_i < \tau$，则将其视为低纯度超节点。于是，低纯度超节点占比定义为
\[
\mathrm{LowPurityRatio}_{\tau}=\frac{1}{M}\sum_{i=1}^{M}\mathbb{I}(p_i<\tau),
\]
其中，$\mathbb{I}(\cdot)$ 为示性函数。该指标用于衡量粗图中标签混杂较严重的超节点所占比例，其值越小，说明粗化结果中存在明显标签混杂问题的超节点越少。本文实验中取 $\tau=0.7$。

结合 \ref{tab:single_label_purity_result} 可以看出，社交数据集的平均标签纯度较高，低纯度超节点占比也基本低于 Cora 与 Citeseer 数据集，说明超节点内部标签一致性并非完全失控。也就是说，原始 UGC 在这些数据集上的问题并不完全来自标签混杂，还可能与超节点特征聚合方式较为粗略有关。由此可以推断，原始 UGC 在社交网络场景下面临的问题并不只是“是否成功聚合了相同标签节点”，还涉及超节点特征表示是否能够充分保留对分类任务有用的判别信息。换言之，原始 UGC 在超节点特征聚合方式上仍存在进一步优化空间。

\textbf{（2）多标签数据集上的问题分析。}  

多标签社交网络中，同一节点通常可以同时具有多个标签，这些标签可能对应用户的兴趣、身份、行为属性或社群关系。

多标签会影响 UGC 中的关键参数与粗化流程。UGC 通过异配系数 $\alpha$ 调节结构信息与特征信息在增强节点表示中的作用，而 $\alpha$ 的计算依赖于边两端节点是否属于同类。当节点具有多个标签时，节点之间是否属于“同类”不再能够由单一标签直接判断，而不同的同类判定规则会导致不同的 $\alpha$ 取值，并进一步影响增强特征构造、哈希分桶和超节点聚合结果。因此，多标签处理方式并非简单的数据预处理步骤，而是会系统性影响 UGC 整体行为的重要因素。

综上，多标签社交网络给 UGC 带来的主要问题包括：多标签节点之间同类关系难以统一定义，异配系数计算依赖标签处理规则，粗化后超节点标签生成可能造成语义损失，以及不同标签处理方式可能改变下游分类任务的类别空间和难度。基于这些问题，后续章节将进一步设计多种多标签处理策略，并通过实验比较其对 UGC 粗化结果和分类性能的影响。

\textbf{（3）问题总结。}  
综合以上分析可以看出，UGC 在社交网络场景下的主要问题具有明显的双重性：对于单标签数据集，问题主要表现为谱性质保持较好，但下游分类性能仍存在提升空间，说明原始超节点特征表示方式仍不够充分；对于多标签数据集，问题则主要表现为标签处理方式缺乏统一标准，不同策略会显著影响类别空间、异配系数和分类结果，从而影响 UGC 的整体适用性。基于这些问题，本文后续将分别针对单标签数据集和多标签数据集开展优化设计：前者重点改进粗化质量评价与超节点特征表达，后者重点研究多标签处理策略及其对 UGC 粗化结果的影响。

\subsection{面向单标签数据集的优化设计}

根据前文问题分析可知，UGC 在部分单标签社交网络数据集上能够较好保持谱性质，但下游节点分类效果仍不理想。进一步结合平均标签纯度和低纯度超节点占比可以发现，部分数据集的超节点内部标签一致性并未出现明显失控，说明分类性能不足并不能完全归因于标签聚合错误。因此，本文将优化重点从超节点标签层面进一步转向超节点特征表示层面，重点分析原始特征聚合方式是否能够充分保留对分类任务有价值的判别信息。

在原始 UGC 流程中，粗化后超节点的特征由其内部成员节点特征进行平均聚合得到。设第 $i$ 个超节点为 $S_i$，其包含的原始节点集合为
\[
S_i=\{v_{i1},v_{i2},\cdots,v_{im}\},
\]
节点 $v$ 的原始特征向量记为 $x_v$。则原始平均特征聚合方式可表示为
\[
x_i^{c}=\frac{1}{|S_i|}\sum_{v\in S_i}x_v,
\]
其中，$x_i^{c}$ 表示第 $i$ 个超节点的特征表示。该方法实现简单，能够在一定程度上反映超节点内部成员节点的整体特征分布，但其隐含假设是同一超节点内所有成员节点对超节点表示的贡献完全相同。

然而，在社交网络数据中，即使多个节点被聚合到同一超节点，其特征对超节点整体语义的贡献也可能存在差异。一方面，部分节点可能更接近超节点内部的主流特征模式，能够更好代表该超节点；另一方面，部分节点虽然与其他节点被划入同一超节点，但其特征可能处于边缘位置或包含较多噪声。如果对所有成员节点采用完全相同的权重进行平均，可能会削弱代表性节点的贡献，并放大边缘节点或噪声节点对超节点特征的影响，从而影响后续 GNN 分类效果。因此，有必要在超节点特征构建过程中引入成员节点的重要性差异。

基于上述考虑，本文提出一种基于相似度的加权特征聚合方法。该方法首先以超节点内部成员节点特征的均值作为超节点原型表示，记为
\[
\bar{x}_i=\frac{1}{|S_i|}\sum_{v\in S_i}x_v.
\]
随后，计算每个成员节点特征与该超节点原型之间的余弦相似度：
\[
s_v=\frac{x_v \cdot \bar{x}_i}{\|x_v\|_2\|\bar{x}_i\|_2}, \quad v\in S_i.
\]
其中，$s_v$ 表示节点 $v$ 与其所属超节点原型之间的相似程度。相似度越高，说明该节点越接近超节点内部的主要特征模式，也更适合作为超节点特征表示的主要贡献来源。

在获得相似度后，本文采用 softmax 函数将相似度转换为归一化权重：
\[
w_v=\frac{\exp(\gamma s_v)}{\sum_{u\in S_i}\exp(\gamma s_u)}, \quad v\in S_i,
\]
其中，$\gamma$ 为温度参数，用于调节权重分布的集中程度。当 $\gamma$ 较小时，不同成员节点的权重差异相对较小，加权聚合更接近普通平均；当 $\gamma$ 较大时，相似度较高的节点会获得更大权重，从而增强代表性节点对超节点特征的影响。

最终，第 $i$ 个超节点的加权特征表示定义为
\[
x_i^{c}=\sum_{v\in S_i} w_v x_v.
\]
与原始平均聚合方法相比，该方法能够根据成员节点与超节点原型的相似程度自适应分配权重，使超节点特征更加偏向内部主流特征模式，从而减少特征离群点或噪声节点对粗图表示的影响。

该优化方法并不改变 UGC 已经得到的节点聚合关系和粗图邻接结构，而仅对超节点特征生成方式进行调整。因此，该方法能够在保留原有粗化结构和谱性质分析基础的同时，进一步改善粗图特征表示，为后续下游 GNN 分类任务提供更具判别性的输入特征。具体实验效果将在后续 3.5 实验设计与结果分析部分中进行说明。

\subsection{面向多标签数据集的优化设计}

在多标签社交网络中，一个节点可能同时对应多个标签，节点标签可以表示为一个标签集合或标签序列。设节点 $v_i$ 的标签集合为
\[
L_i=\{l_{i1},l_{i2},\cdots,l_{ik}\},
\]
其中 $k$ 表示节点所具有的标签数量。与单标签数据不同，多标签数据中两个节点是否属于同类并没有唯一标准。如果直接将多标签数据压缩为单标签表示，可能会损失标签之间的交叠关系；如果直接使用完整标签集合，又会给异配系数计算、UGC 输入标签生成和超节点标签确定带来困难。因此，本文针对多标签数据集设计了多种标签处理策略，用于比较不同同类关系定义对 UGC 粗化结果的影响。

UGC 中的异配系数 $\alpha$ 用于衡量图中连接两端节点标签不同的比例，并进一步影响增强节点表示的构造。对于多标签数据，本文首先定义一个同类判定函数
\[
\delta(v_i,v_j)=
\begin{cases}
1, & v_i \text{ 与 } v_j \text{ 被判定为同类},\\
0, & v_i \text{ 与 } v_j \text{ 被判定为异类}.
\end{cases}
\]
在此基础上，多标签场景下的异配系数可写为
\[
\alpha=\frac{\sum_{(v_i,v_j)\in E_l}\left(1-\delta(v_i,v_j)\right)}{|E_l|},
\]
其中，$E_l$ 表示边两端节点均具有有效标签的边集合。由此可见，不同的同类判定函数会直接影响 $\alpha$ 的取值，并进一步影响 UGC 的节点表示增强和粗化结果。因此，多标签优化的核心在于设计合理的标签处理策略，使其既能表达多标签语义，又能适配 UGC 的计算流程。

本文设计并实现了四种多标签处理策略，分别记为 V1、V2、V3 和 V4。

\textbf{（1）V1：第一标签策略。}  
V1 策略将每个节点标签序列中的第一个标签作为该节点的代表标签。设节点 $v_i$ 的第一个标签为 $l_{i1}$，则两个节点的同类判定规则为
\[
\delta_{V1}(v_i,v_j)=
\begin{cases}
1, & l_{i1}=l_{j1},\\
0, & l_{i1}\neq l_{j1}.
\end{cases}
\]
该策略实现简单，能够直接将多标签数据转化为单标签形式，便于复用原始 UGC 流程。但其不足在于只保留第一个标签，忽略了节点的其他标签信息，可能造成多标签语义损失。

\textbf{（2）V2：标签集合交集策略。}  
V2 策略从标签集合角度判断两个节点是否具有共同标签。若两个节点标签集合存在交集，则认为二者属于同类；否则认为二者属于异类。其同类判定规则为
\[
\delta_{V2}(v_i,v_j)=
\begin{cases}
1, & L_i\cap L_j\neq \varnothing,\\
0, & L_i\cap L_j= \varnothing.
\end{cases}
\]
该策略能够充分利用标签重叠信息，适合刻画“只要存在共同兴趣或属性即可视为相似”的场景。但当标签集合之间交叠较多时，该策略可能导致大量节点被归入同一类别，从而压缩类别空间并降低分类任务的区分度。

\textbf{（3）V3：位置对齐匹配策略。}  
V3 策略将多标签序列中的标签位置纳入考虑，只有当两个节点在相同位置上存在相同标签时，才认为二者具有同类关系。设节点 $v_i$ 和 $v_j$ 的标签序列分别为 $(l_{i1},l_{i2},\cdots)$ 和 $(l_{j1},l_{j2},\cdots)$，则同类判定规则为
\[
\delta_{V3}(v_i,v_j)=
\begin{cases}
1, & \exists r,\ l_{ir}=l_{jr},\\
0, & \forall r,\ l_{ir}\neq l_{jr}.
\end{cases}
\]
与 V2 相比，V3 不仅考虑标签是否相同，还考虑标签在序列中的位置，因此能够在一定程度上保留标签顺序或标签主次关系。该策略适用于标签顺序具有一定语义含义的数据，但如果标签顺序本身并不稳定，则可能降低同类关系判定的鲁棒性。

\textbf{（4）V4：Jaccard 阈值策略。}  
V4 策略通过标签集合之间的 Jaccard 相似度判断节点是否属于同类。两个节点的标签集合相似度定义为
\[
J(L_i,L_j)=\frac{|L_i\cap L_j|}{|L_i\cup L_j|}.
\]
给定阈值 $\theta$，若 $J(L_i,L_j)\geq \theta$，则认为两个节点属于同类；否则认为二者属于异类：
\[
\delta_{V4}(v_i,v_j)=
\begin{cases}
1, & J(L_i,L_j)\geq \theta,\\
0, & J(L_i,L_j)<\theta.
\end{cases}
\]
该策略相比 V2 更加严格，能够避免只因一个标签重合就将两个节点视为同类的问题，同时又比 V1 更充分地利用了多标签集合信息。本文实现中将 Jaccard 阈值作为可配置参数，以便根据不同数据集的标签重叠程度进行调整。

在具体流程上，面向多标签数据集的优化设计主要包括以下步骤：
\begin{enumerate}
    \item 读取原始多标签文件，将每个节点的标签表示为集合或序列形式。
    \item 根据选定策略 V1、V2、V3 或 V4 构造同类判定函数 $\delta(v_i,v_j)$。
    \item 基于边两端节点的同类判定结果计算异配系数 $\alpha$。
    \item 将多标签数据转化为 UGC 可接受的标签输入形式，并生成对应的预处理数据。
    \item 在相同目标压缩率和模型设置下运行 UGC，比较不同策略对粗化结果和下游分类结果的影响。
\end{enumerate}

通过上述设计，本文将多标签处理从简单的数据格式转换提升为影响 UGC 粗化行为的重要策略选择。不同策略代表了不同的多标签语义假设：V1 强调主标签，V2 强调任意标签重叠，V3 强调标签位置匹配，V4 强调标签集合相似度。具体实验结果将在后续实验设计与结果分析部分中进行比较。

\section{功能性需求}

本文设计的基于 UGC 的图粗化分析系统主要面向图粗化实验分析与结果可视化需求，目标是打通从数据输入、参数配置、图粗化运行到结果展示和 GNN 分类测试的完整流程。系统使用者可以通过 Web 页面完成实验配置、流程执行、粗化结果查看以及下游分类测试，从而降低命令行实验操作成本，提高实验过程的可控性和结果分析的直观性。结合系统建设目标，本文将系统功能性需求划分为以下几个方面。

\textbf{（1）数据集选择与上传功能。}  
系统应支持用户选择内置数据集，也应支持用户上传自定义数据集。对于内置数据集，系统需要能够读取预先存放的数据目录，并在页面中提供可选数据集列表；对于用户上传的数据集，系统需要支持边集文件、标签文件和特征文件的上传，并对上传文件进行基本格式校验。考虑到本文研究同时涉及单标签和多标签社交网络数据，系统还应能够在数据分析阶段识别数据集的节点规模、边规模、特征维度和标签类型等基本信息，为后续参数配置和流程运行提供依据。

\textbf{（2）实验参数配置功能。}  
系统应支持用户在运行实验前配置关键参数，包括标签类型、多标签处理策略、目标压缩率、GNN 模型类型、训练轮数、标定迭代次数以及是否启用谱性质计算等。对于多标签数据集，系统应提供 V1、V2、V3 和 V4 等标签处理策略选项；对于 Jaccard 阈值策略，还应允许用户配置阈值参数。对于优化实验，系统还应提供是否启用低纯度超节点拆分、是否启用相似度加权特征聚合以及相关参数配置入口。通过这些配置，用户能够在统一界面中完成不同实验方案的设定。

\textbf{（3）图粗化流程运行功能。}  
系统应能够根据用户配置自动执行完整的图粗化流程。该流程包括数据分析、数据清洗、Alpha 计算、数据预处理、Bin Width 标定、UGC 粗化以及结果保存等阶段。在运行过程中，系统需要按照阶段记录执行状态和关键中间结果，并在页面中向用户展示当前运行进度。若某一阶段运行失败，系统应能够给出相应错误信息，便于用户定位问题。该功能是系统实现自动化实验流程的核心。

\textbf{（4）粗化结果展示功能。}  
系统应能够在实验完成后展示粗化结果概览，包括数据集名称、标签策略、原始节点数、压缩后超节点数、实际压缩率、类别数、平均标签纯度、低纯度超节点占比以及 GNN 测试状态等信息。对于开启谱性质计算的实验，系统还应展示平均特征值误差、最大特征值误差、最小特征值误差、双曲误差和 Dirichlet Energy 相对误差等指标。通过该功能，用户可以快速了解一次粗化实验的整体效果。

\textbf{（5）图结构可视化与交互功能。}  
系统应支持对粗化后图结构进行可视化展示，并提供一定的交互能力。用户应能够查看粗图中的超节点和超边关系，点击超节点查看其包含的原始节点、主标签分布和邻接超节点信息。同时，系统还应支持原图与粗图之间的映射联动，使用户能够观察某个超节点在原图中对应的成员节点及其局部邻域关系。该功能有助于用户从结构层面理解图粗化结果，提高粗化过程的可解释性。[插图建议：可在系统实现章节配合“粗图预览与原图映射联动界面截图”展示该需求对应的实现效果。]

\textbf{（6）GNN 分类测试功能。}  
系统应支持在粗化结果基础上进行 GNN 分类测试。用户可以在 GNN 测试页面选择模型类型和训练轮数，并基于当前实验生成的粗图数据重新执行分类测试。系统需要记录训练过程状态，并在测试完成后保存分类准确度、Macro-F1 和训练时间等结果。该功能用于验证粗图在下游节点分类任务中的可用性，也是评价图粗化方法效果的重要环节。

\textbf{（7）实验结果保存与导出功能。}  
系统应能够为每次实验创建独立的结果目录，并保存实验状态、实验摘要、运行日志、粗图结构、超节点映射关系、元数据和 GNN 测试结果等文件。同时，系统还应支持将粗化后的数据导出为 PT 格式或文本格式，便于后续复现实验或在其他工具中继续分析。通过文件化保存方式，系统能够较好支持实验记录、结果追踪和后续扩展。

\section{非功能性需求}

除功能性需求外，系统还需要满足一定的非功能性需求，以保证系统在实际使用过程中具有较好的可用性、稳定性、可维护性和扩展能力。结合图粗化实验分析系统的应用特点，本文从以下几个方面对非功能性需求进行说明。

\textbf{（1）可用性需求。}  
系统面向图粗化实验分析场景，使用者可能需要频繁调整数据集、标签策略、目标压缩率和模型参数。因此，系统界面应尽可能简洁清晰，使用户能够通过页面完成实验配置和结果查看，减少直接操作命令行脚本的复杂度。系统应在运行过程中展示当前阶段和关键日志信息，使用户能够了解实验是否正常执行；在结果展示阶段，应通过指标卡片、图表和图结构可视化等方式呈现结果，提高实验分析的直观性。

\textbf{（2）稳定性需求。}  
图粗化实验通常涉及数据读取、预处理、参数标定、算法运行和模型训练等多个环节，任一环节出错都可能导致实验中断。因此，系统需要具备基本的异常处理能力，在数据格式错误、参数不合法、脚本执行失败或结果文件缺失时，能够给出明确的错误提示。同时，系统应记录各阶段的运行状态和日志信息，便于后续排查问题。对于运行时间较长的实验，系统还应能够持续保存状态，避免用户无法判断任务进度。

\textbf{（3）可维护性需求。}  
系统后端应采用清晰的模块划分，避免将数据处理、算法调用、页面路由和结果解析全部耦合在同一逻辑中。本文系统将数据分析、数据清洗、Alpha 计算、预处理、桶宽标定、UGC 粗化和 GNN 测试等环节封装为不同服务模块，有利于后续定位问题和修改功能。前端页面也应按照上传配置、运行监控、结果展示和 GNN 测试等功能进行组织，使系统结构清晰、代码职责明确。

\textbf{（4）可扩展性需求。}  
由于图粗化方法、标签处理策略和 GNN 模型都可能继续扩展，系统应具备一定的扩展能力。具体而言，系统应能够方便地增加新的数据集、标签处理策略、粗化参数、优化方法和分类模型。例如，在多标签处理策略方面，系统应支持在现有 V1 至 V4 策略基础上继续增加新的标签相似性定义；在 GNN 测试方面，系统应支持接入新的图神经网络模型；在可视化方面，系统应能够扩展更多指标图表和交互方式。

\textbf{（5）实验可复现性需求。}  
本文系统不仅用于展示粗化结果，也用于支撑实验分析，因此需要保证实验过程和结果具有较好的可复现性。系统应为每次实验生成独立的实验编号，并保存参数配置、运行日志、粗图结构、映射关系、评价指标和 GNN 测试结果等文件。通过结构化保存实验信息，用户可以追溯一次实验的输入参数和输出结果，也可以在后续研究中复用粗图数据和中间结果。

\textbf{（6）性能需求。}  
社交网络数据通常具有节点数多、边数多和特征维度高等特点，因此系统需要在算法执行和结果展示方面具有一定性能保障。在后端运行过程中，系统应尽量复用已有脚本和中间结果，减少重复计算；在前端可视化过程中，对于规模较大的粗图或原图映射关系，应采用边筛选、局部展示或异步加载等方式，避免页面渲染压力过大。通过这些设计，系统能够更好地适应不同规模数据集的实验分析需求。

\subsection{系统总体架构设计}

根据前文需求分析，本文设计的图粗化分析系统采用浏览器/服务器（Browser/Server，B/S）架构。用户通过浏览器访问系统，在前端页面完成数据集选择、实验参数配置、流程运行和结果查看；服务器端基于 Flask 框架接收用户请求，调度 Python 算法流程，并将实验结果以结构化形式返回前端。系统总体架构如图所示。[插图建议：可在此处插入“系统总体架构图”，展示用户端、Web 服务端、算法处理模块和数据存储模块之间的关系。]

从功能职责上看，系统总体结构可以划分为用户交互层、业务处理层、算法计算层和数据存储层四个部分。

\begin{enumerate}
    \item 用户交互层主要由 HTML 页面、CSS 样式和 JavaScript 脚本构成，面向系统使用者提供数据上传、参数配置、运行状态查看、粗化结果展示和 GNN 分类测试等交互功能。其中，图结构展示和统计结果展示分别结合 Cytoscape.js 和 ECharts 等前端可视化工具实现，是用户使用系统的直接入口。
    \item 业务处理层以 Flask Web 应用为核心，负责连接前端页面与底层算法流程，主要完成请求解析、实验任务创建、流程调度、状态维护和结果返回等工作。该层将用户在页面中的配置转换为后端可执行的实验任务，并负责向前端反馈运行状态和结果信息。
    \item 算法计算层主要由 Python 脚本和图学习相关计算程序组成，是系统实现图粗化分析功能的核心。该层完成数据分析与清洗、Alpha 计算、多标签预处理、Bin Width 标定、UGC 图粗化、谱性质计算、标签纯度统计、特征聚合优化以及 GNN 分类测试等任务，使系统能够自动完成从原始数据到粗化结果的生成。
    \item 数据存储层采用文件化方式组织数据，不依赖独立数据库。该层用于保存内置数据集、用户上传数据、中间处理结果、运行日志、粗化结果和分类测试结果，为实验复现、结果导出和可视化展示提供数据支撑。
\end{enumerate}

在系统运行过程中，用户首先在前端页面选择或上传数据集，并配置标签处理策略、目标压缩率、优化方法和分类测试模型等参数；随后 Flask 后端根据用户配置创建实验任务，并调用 Python 算法流程依次完成数据预处理、参数标定、图粗化和分类测试等步骤；实验结果生成后写入文件化结果目录，并由前端页面读取和展示粗化指标、图结构、超节点映射关系以及 GNN 分类结果。

\subsection{GNN 分类测试模块实现}

GNN 分类测试模块用于在粗化结果基础上进一步验证粗图对下游节点分类任务的支持能力。系统在测试页面中提供模型选择与测试入口，当前支持的模型包括 GCN、GraphSAGE、GAT、GIN、APPNP 和 3WL 等。用户在页面中选择模型类型和训练轮数后，前端将测试请求提交至后端，后端读取当前实验对应的粗图数据和实验参数，并启动相应的分类测试流程。

为了改善交互体验，系统在该页面中设计了异步提交与轮询更新机制。用户点击“开始测试”后，前端页面会显示加载遮罩，并持续从后端获取当前测试状态和训练轮次；测试完成后，页面自动刷新以展示最新结果。系统在页面中同时保留最近一次测试结果和历史记录列表，便于用户比较不同模型或不同训练轮数下的分类表现。通过该模块，系统实现了图粗化分析与下游学习任务验证的衔接，使整个实验平台具备了更完整的研究支撑能力。[插图建议：可在此处插入“GNN 分类测试页面截图”，重点展示模型选择区、训练进度提示区和历史测试结果区。]
